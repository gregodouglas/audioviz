# AI disclosure

audioviz is built with generative AI, and most of it was written by AI. This file says how, so that nobody has to guess.

## Who did what

**The code was written by Claude Code**, Anthropic's coding agent: the Rust, the WGSL shaders, the build and release scripts, the installer script, the tests and these docs, including this file. Two models wrote it: Claude Fable 5.1 and Claude Opus 5.5. Every commit in the history carries a `Co-Authored-By: Claude …` trailer naming the model that worked on it (194 of 194 commits as of 0.4.76), so `git log` is the full record.

**Greg Douglas directs the project.** He decides what gets built and how it should look and move, and he picks the inspiration it follows. He reviews the results on screen against real music, runs the tests that need a person (mouse, installer, TV casting), makes the design calls recorded in [`docs/decisions/`](docs/decisions/), and decides what ships. When a visual is "after" someone else's work, Greg chose the source and Claude worked from a description of it (see below).

So "written by" in this repository means generated by Claude Code from Greg's direction, then checked, corrected and accepted by Greg. It does not mean typed by hand.

## What was not generated

- **Pictures.** No image, video or audio generation model was used. Every image in `docs/img/` is a screenshot of the app or a render made by the repo's own code (`cargo xtask mockup`, `cargo xtask icon`); the visuals draw everything they show from code at run time.
- **Third-party work** keeps its own authors and licences: the fonts (Inter and JetBrains Mono, SIL Open Font License) and the Rust crates listed in the README. Ideas taken from other visualizers are credited in [`docs/INSPIRATION.md`](docs/INSPIRATION.md).

## Inspiration and copying

Several visuals follow other people's visualizers (Uberviz, vizz.fm, audible-visuals). For those, no source code was copied or shown to the AI. Claude worked from what the original looks like: its public pages, or Greg's description of it playing. Each such visual says "No code used; written new with Claude Code" in its credit line, which appears in the app's panel, and is listed in `docs/INSPIRATION.md` with the source's author and licence.

AI models learn from large amounts of public code, so a well-known technique can come out in a familiar shape. Where we recognise a named algorithm (a distance function, a noise), its author and licence are credited in the code and in `docs/INSPIRATION.md`. If you find something in audioviz that looks like your code, please open an issue. We will credit it properly or replace it.

## Checks on the output

AI output here is treated like any contributor's code. It is not trusted on faith:

- CI builds and tests every push on Windows and macOS. `cargo deny` checks dependency licences and advisories, and bans every network crate (see [`PRIVACY.md`](PRIVACY.md)).
- Visuals are judged on screen. The lab (`audioviz-lab`, [ADR-0003](docs/decisions/ADR-0003-lab.md)) renders them identically every run, and the app is run on real music before anything is accepted. Performance is measured, not estimated.
- The design record (`docs/decisions/`, the phase logs in `docs/`) says what was decided, by whom and why.

## The app itself

The app has no AI in it. It runs no model, calls no AI service, and sends nothing anywhere (see `PRIVACY.md`). The analysis that drives the visuals (bands, beats, chroma) is ordinary signal processing in `crates/analysis`.
